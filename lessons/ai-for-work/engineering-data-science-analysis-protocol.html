Engineering Data Science Analysis Protocol

Use a disciplined, gated workflow to convert engineering data into statistically defensible, physically credible, reproducible, and decision-ready recommendations.

What you will learn

  • Frame an engineering decision before selecting a method.
  • Audit grain, lineage, measurement quality, confounding, and leakage.
  • Select and validate models that match process structure.
  • Translate output into operational risk and action.
  • Use AI prompts without surrendering technical judgment.

How to use this lesson

Work through the phases in order. Treat each gate as a stop/go review. Use the phase prompts as reusable AI instructions, then verify every output against process knowledge and source evidence.

Learning objectives

What you will be able to do

  • Define an engineering decision, response, population, unit of analysis, and success criterion.
  • Identify data-grain, lineage, measurement, confounding, and leakage risks.
  • Select a proportionate analysis and validation strategy.
  • Interpret statistical output using engineering knowledge and uncertainty.
  • Apply reusable AI prompts while retaining human review and accountability.

Prerequisites

Basic familiarity with engineering data, descriptive statistics, and spreadsheets is helpful. No programming knowledge is required.

Concept in plain English

What this protocol is—and is not

This protocol is a repeatable way to move from a workplace question to a defensible decision. It asks what decision is being made, whether the data are fit for that decision, which method matches the process structure, and how uncertainty changes the recommendation.

It is used when an analysis could influence a process setting, quality disposition, model, investment, or operational action. It does not make weak data trustworthy, prove causation from association, or replace engineering judgment.

Key terminology

TermPlain-language meaningPractical interpretation
Data grainWhat one row represents.Heat-level and specimen-level rows cannot be joined casually.
ConfounderA third factor linked to both the input and outcome.A temperature effect may actually be a grade or rolling-practice effect.
LeakageFuture or outcome information entering model development.Reported model accuracy becomes unrealistically optimistic.
ExtrapolationPredicting beyond observed conditions.Uncertainty and technical risk increase outside historical support.
ValidationTesting whether conclusions remain reliable.Use time-, group-, or process-aware checks that match deployment.

1. Purpose and Scope

This protocol defines the minimum analytical steps required before engineering data is used to support a process change, quality disposition, operating recommendation, technical risk assessment, predictive model, optimization study, or management decision.

It is suitable for analyses involving:

Regression Mixed-effects models DOE SPC Reliability Classification Time series Root-cause analysis Process optimization Quality risk
Primary objective: produce conclusions that are statistically valid, physically plausible, operationally useful, traceable to source data, and robust enough to withstand technical review.

2. Governing Principles

PrincipleRequired behavior
Decision-first analysisDefine the decision, risk, and success criterion before selecting a method.
Data quality before modelingNo inferential or predictive model should proceed until data quality risks are documented.
Engineering plausibilityStatistical relationships must be assessed against physical and process knowledge.
Uncertainty disclosurePredictions must include uncertainty, not only point estimates.
Confounding awarenessAlternative explanations, grade effects, practice effects, equipment effects, and time effects must be tested.
ReproducibilityData source, transformations, exclusions, code, assumptions, and model settings must be recorded.
Model proportionalityUse the simplest model that adequately answers the decision question.
Independent challengeActively attempt to disprove the preferred conclusion before acceptance.

Phase 0 — Analysis Intake

Before touching the data, record the request in a structured intake form.

  • Project title and analysis owner
  • Decision-maker and affected stakeholders
  • Operational or business decision to be supported
  • Required completion date
  • Consequence of a wrong conclusion
  • Available data sources and known limitations
  • Required output format: technical report, presentation, dashboard, model, or recommendation
Gate 0 — Proceed?
Proceed only when the decision question and intended use of the result are explicit.

  1. Create a complete analysis intake from the information I provide. Identify missing information before proceeding.
  2. List every stakeholder, decision, risk, and required deliverable for this project.
  3. Rewrite my problem statement into a precise engineering decision statement.
  4. Identify ambiguities in my request that could invalidate the analysis later.
  5. Generate a project charter using engineering best practices.

Phase 1 — Problem Definition

1.1 Convert the request into an analytical question

A strong problem statement identifies the response, predictors, population, comparison, decision threshold, and operating context.

Weak:
Determine whether temperature affects Charpy energy.

Strong:
Estimate the effect of exit temperature on transverse base-metal Charpy energy
after controlling for grade, OD, wall thickness, rolling practice, slab thickness,
chemistry, coiling temperature, and test temperature. Quantify the probability
that a proposed X65 product will meet the specified average and minimum requirements.

1.2 Define the analysis framework

ItemRequired definition
Response variableWhat outcome is being explained, predicted, controlled, or optimized?
Unit of analysisHeat, slab, coil, test specimen, pipe, shift, batch, day, or campaign?
PopulationWhat products, grades, assets, periods, and operating conditions are in scope?
Success criterionSpecification, target, tolerance, economic threshold, or risk limit.
Primary hypothesisThe relationship or difference being evaluated.
Alternative explanationsKnown confounders and competing mechanisms.
Decision errorWhat are the consequences of false positive and false negative conclusions?
Do not select a regression, DOE, machine-learning model, or control chart until the unit of analysis and decision objective are defined.

AI Prompt Library

Use or adapt the following prompts to obtain high-quality, structured assistance from AI during this phase.

  1. Convert this business problem into statistically testable hypotheses.
  2. Identify the response variable, predictors, confounders, and unit of analysis.
  3. Challenge my assumptions and propose alternative explanations.
  4. Determine the most appropriate analytical objective and success criteria.
  5. Identify decisions that depend on this analysis and their risks.

Phase 2 — Data Acquisition and Lineage

2.1 Establish the data grain

Every table must have a clearly defined grain. Combining tables of different grain without aggregation rules can create duplicate observations and false statistical confidence.

  • Document the row definition for every source table
  • Identify primary and foreign keys
  • Confirm one-to-one, one-to-many, or many-to-many joins
  • Test whether joins duplicate the response variable
  • Record all filters and exclusions
  • Preserve a raw, unchanged extract

2.2 Data lineage record

FieldExample
Source systemQADW, historian, laboratory database, ERP, manual workbook
Source table/viewFully qualified table or file name
Extraction dateDate and time pulled
Date rangeEarliest and latest production/test date
FiltersGrade, facility, product, valid test type, date, status
Join keysHeat number, slab ID, coil ID, sample ID
TransformationsAggregations, conversions, derived columns, normalization

AI Prompt Library

Use or adapt the following prompts to obtain high-quality, structured assistance from AI during this phase.

  1. Design the ideal dataset schema and required joins for this analysis.
  2. Review my SQL query for duplicate risks and grain mismatches.
  3. Identify missing source tables or variables that should be collected.
  4. Produce a complete data lineage document.
  5. Audit my joins for one-to-many and many-to-many problems.

Phase 3 — Data Quality Gate

No model should proceed until the dataset is assessed against the following dimensions.

Structural checks

  • Duplicate rows and duplicate business keys
  • Unexpected many-to-many joins
  • Missing records caused by filters or failed joins
  • Incorrect data types
  • Inconsistent category labels
  • Mixed units
  • Timestamp and timezone inconsistencies

Measurement checks

  • Impossible or physically implausible values
  • Instrument resolution and rounding
  • Calibration or method changes
  • Censoring and detection limits
  • Retests and replacement results
  • Operator, machine, and laboratory effects
  • Measurement-system capability

3.1 Missing data analysis

Report missingness by variable, time period, product, grade, asset, and operational subgroup. Determine whether data are plausibly missing completely at random, missing at random, or missing not at random.

3.2 Outlier handling

Do not remove an observation only because it is statistically unusual. Classify each outlier as:

ClassificationAction
Data errorCorrect from source evidence or exclude with documented reason.
Measurement failureInvestigate test validity and instrument condition.
Valid extreme process conditionRetain and evaluate influence.
Special causeAnalyze separately if the decision concerns stable operation.
UnknownRetain, flag, and run sensitivity analysis with and without the point.
Gate 3 — Data quality disposition
Classify the dataset as Fit for purpose, Fit with limitations, or Not fit for purpose. Record all unresolved risks before continuing.

AI Prompt Library

Use or adapt the following prompts to obtain high-quality, structured assistance from AI during this phase.

  1. Perform a complete engineering data-quality audit before modeling.
  2. Identify missing values, duplicates, impossible values, and inconsistent units.
  3. Look for data leakage and hidden sampling bias.
  4. Recommend treatment for every outlier with justification.
  5. Determine whether this dataset is fit for purpose.

Phase 4 — Exploratory Data Analysis

Exploration is used to understand the data structure. It is not the final basis for causal conclusions.

Minimum exploratory outputs

  • Response distribution and subgroup distributions
  • Time-order plot
  • Scatterplots for continuous predictors
  • Boxplots or interval plots for categorical predictors
  • Correlation matrix for numeric variables
  • Counts per subgroup and predictor combination
  • Missingness map
  • Outlier and leverage screening
  • Process sequence or campaign effects
  • Potential nonlinear patterns and interactions

Confounding and Simpson’s paradox checks

For each apparent relationship, stratify or condition on major process variables. A pooled trend may disappear or reverse when examined within grade, product, rolling practice, slab thickness, line, or time period.

A strong pooled correlation is not sufficient evidence of a process mechanism. Verify that the relationship exists within relevant operating groups.
Gate 4 — Exploration review
Confirm that key subgroup structure, time effects, rare combinations, and confounders have been identified before model construction.

AI Prompt Library

Use or adapt the following prompts to obtain high-quality, structured assistance from AI during this phase.

  1. Perform exploratory analysis without drawing conclusions.
  2. Identify hidden clusters, subgroup effects, and nonlinear relationships.
  3. Test for Simpson's paradox and confounding.
  4. Recommend the most informative visualizations.
  5. Summarize insights that require confirmatory testing.

Phase 5 — Feature Engineering

Derived variables should reflect process knowledge rather than arbitrary mathematical manipulation.

Acceptable feature categories

  • Unit conversions and standardized units
  • Process deltas, such as exit minus coiling temperature
  • Rates, ratios, residence times, and specific energy
  • Chemistry equivalents and metallurgical indices
  • Lagged or rolling process variables
  • Product geometry terms
  • Interactions supported by engineering mechanisms
  • Grouped categorical factors for equipment, practice, or campaign

Feature rules

RuleReason
Create features before splitting only when they do not use outcome information.Prevents data leakage.
Center continuous variables before creating polynomial or interaction terms.Improves interpretability and numerical stability.
Retain parent terms when interactions are included.Preserves model hierarchy.
Avoid redundant variables representing the same physical quantity.Reduces multicollinearity and unstable coefficients.
Document every derived formula.Ensures reproducibility.

AI Prompt Library

Use or adapt the following prompts to obtain high-quality, structured assistance from AI during this phase.

  1. Recommend engineered features based on process knowledge.
  2. Identify useful interaction terms and polynomial effects.
  3. Detect redundant predictors and multicollinearity risks.
  4. Explain every engineered feature in engineering language.
  5. Prioritize features by expected predictive value.

Phase 6 — Model Strategy and Comparison

The model family must match the response type, data structure, and decision objective.

SituationCandidate method
Continuous response, interpretable effectsMultiple linear regression or general linear model
Repeated tests, heats, coils, batches, operators, or campaignsMixed-effects model
Pass/fail or defect probabilityBinary logistic regression
Counts of events or defectsPoisson or negative binomial model
Nonlinear response with known functional formNonlinear regression
Many correlated predictorsRidge, LASSO, or elastic net
Complex prediction with nonlinear interactionsRandom forest or gradient boosting
Time-dependent process behaviorTime-series or state-space model
Designed process studyANOVA, factorial DOE, response surface methodology

6.1 Baseline model

Always fit a simple baseline model. Complex methods must demonstrate a meaningful improvement over the baseline.

6.2 Model comparison criteria

  • Prediction error on unseen data
  • Adjusted R², AIC, BIC, or likelihood-based criteria where appropriate
  • Calibration
  • Residual behavior
  • Stability across subgroups and time periods
  • Interpretability
  • Operational deployability
  • Consistency with engineering knowledge
The best engineering model is not automatically the model with the highest R². Prefer the model that gives adequate accuracy, stable behavior, transparent assumptions, and actionable interpretation.

AI Prompt Library

Use or adapt the following prompts to obtain high-quality, structured assistance from AI during this phase.

  1. Compare all appropriate statistical and machine-learning models.
  2. Recommend the simplest defensible model and explain why.
  3. Rank candidate models by accuracy, interpretability, and deployment risk.
  4. Identify assumptions for each model family.
  5. Explain when a mixed-effects model is preferable.

Phase 7 — Validation and Stress Testing

7.1 Select the correct validation design

Data structurePreferred validation
Independent observationsRandom train/test split or repeated cross-validation
Multiple rows from the same heat, coil, batch, or subjectGrouped split
Time-ordered process dataForward-chaining or time-based holdout
Rare grade or product combinationsLeave-group-out validation and extrapolation review
Small engineering datasetBootstrap, cross-validation, and uncertainty emphasis

7.2 Regression diagnostics

  • Residuals versus fitted values
  • Normal probability plot where inference depends on normality
  • Constant variance
  • Independence and time-order behavior
  • Influential observations and Cook’s distance
  • Leverage
  • Variance inflation factors
  • Specification errors and omitted nonlinear terms

7.3 Sensitivity analysis

  • Fit with and without influential observations
  • Compare alternative subgroup definitions
  • Test alternate missing-data treatments
  • Test alternate model forms
  • Test plausible measurement error
  • Evaluate prediction under nearby operating conditions
  • Assess whether conclusions depend on a small number of groups

7.4 Extrapolation control

For every prediction, compare requested predictor values with the historical data range and combinations. A value may be within each individual variable’s range but still represent an unseen combination.

Gate 7 — Model acceptance
Accept the model only when validation performance, residual behavior, subgroup stability, and extrapolation risk are documented.

Phase 8 — Engineering Interpretation

Translate statistical output into process language.

Required interpretation questions

  • What physical mechanism could explain the relationship?
  • Is the direction of effect credible?
  • Is the magnitude practically important?
  • Does the effect hold within relevant product and process groups?
  • Could the variable be acting as a proxy for another process condition?
  • Is the effect controllable in operation?
  • Would changing this variable create a trade-off elsewhere?

Coefficient interpretation format

Statistical statement:
Holding the other model variables constant, a 10°C increase in exit temperature
is associated with an estimated 6 J reduction in average Charpy energy.

Engineering statement:
Within the historical operating range represented by the model, higher exit
temperature is associated with lower toughness after accounting for the listed
process and chemistry variables. This relationship should not be interpreted
as causal unless supported by a controlled trial or stronger process evidence.

Phase 9 — Decision and Risk Analysis

Convert the model into a decision statement, not merely a statistical conclusion.

Minimum decision outputs

  • Point prediction or estimated effect
  • Confidence interval
  • Prediction interval where an individual future result matters
  • Probability of meeting the specification or target
  • Probability of an adverse outcome
  • Sensitivity to uncertain inputs
  • Extrapolation classification
  • Operational recommendation
  • Required safeguards or verification plan

4. Final Peer-Review Checklist

Before release, perform an adversarial review using the following questions.

  • Could the conclusion be caused by confounding?
  • Could Simpson’s paradox be present?
  • Was the data grain handled correctly?
  • Were repeated observations treated as independent?
  • Could data leakage inflate performance?
  • Does the validation method match the data structure?
  • Are influential points driving the result?
  • Are key predictor combinations absent from the historical data?
  • Is the model extrapolating?
  • Are statistical significance and practical significance being confused?
  • Are assumptions supported by diagnostics?
  • Does the physical mechanism make sense?
  • Are uncertainty and limitations clearly communicated?
  • Can another analyst reproduce the result?
  • Would the recommendation change under a reasonable alternative model?
Release decision
Mark the analysis as Approved, Approved with limitations, or Not approved.

Worked example

Separating temperature from rolling-practice effects

Problem: A pooled chart suggests that higher exit temperature lowers Charpy energy. Management must decide whether to tighten the temperature window.

  1. Define the unit: one slab, with specimen results summarized using a documented aggregation rule.
  2. Audit the structure: the high-temperature observations are concentrated in different rolling practices.
  3. Test the alternative explanation: compare temperature–Charpy relationships within product and rolling practice, then fit a model controlling for grade, geometry, chemistry, practice, slab thickness, coiling temperature, and test temperature.
  4. Validate: use grouped validation by heat or campaign and inspect influential observations and unsupported combinations.
  5. Decide: if the pooled trend disappears within practice, do not attribute the change to temperature alone. Recommend a controlled trial or additional balanced data.

Interpretation: the protocol prevents a correlation created by operating mix from being presented as a physical temperature effect. The limitation is that historical data may still lack the combinations needed for a causal conclusion.

Interpretation guide

When you see thisIt means thisRequired response
Pooled and within-group trends disagreeConfounding or Simpson’s paradox may be present.Report subgroup results and control the relevant factors.
Random validation is much stronger than grouped validationRelated records may be leaking across folds.Use a split that matches future deployment.
Prediction is outside historical rangesThe result is extrapolation.Increase caution, disclose uncertainty, and consider a trial.
Model fit is high but residuals show structureThe model has missed process behavior.Revisit the model form and process variables.

Common mistakes and review traps

  1. Calculation: duplicating the response through a one-to-many join. Check row counts and business keys before and after every join.
  2. Interpretation: treating correlation or a small p-value as causation. Test competing explanations and use process knowledge.
  3. Assumption: deleting every unusual point. Classify each point and run sensitivity checks.
  4. Software output: selecting the model with the highest R². Compare out-of-sample error, diagnostics, stability, and interpretability.
  5. Exam/review trap: reporting a point prediction without an interval or support check. State uncertainty and whether the case is interpolation or extrapolation.

Practice activity

Choose the next analytical action

A model predicts tensile strength using 2,400 specimen rows. Several specimens come from the same heat, and a random train/test split reports excellent accuracy. What should you do before accepting the result?

Answer: repeat validation with all specimens from each heat kept in the same fold or holdout set.

Reasoning: random row splitting lets closely related specimens from one heat appear in both training and test data. That leakage can inflate accuracy. Compare the grouped result with the random result, document the gap, and use the grouped estimate for deployment decisions.

Final summary

Key takeaways

  • Start with the decision, risk, population, and unit of analysis.
  • Do not model until data grain, lineage, measurement quality, and fitness are documented.
  • Challenge pooled relationships using subgroup and time-aware analysis.
  • Match validation to how the model will be used.
  • Report uncertainty, historical support, and extrapolation status.
  • Use AI to structure and challenge work, not to replace verification or accountability.

Decision rule: proceed only when the evidence is fit for the intended decision and the remaining uncertainty is acceptable for the consequence of being wrong.

Remember this: decision first, data quality second, modeling third.
