## Functional verification design

The default protected package still disables complete Mock A. Tests remove the hold only in memory after asserting it is present, then restore it by reloading. No live account, production permission, migration or deployment is involved.

The policy suite verifies both timing modes, reveal denial, mixed correct/wrong/blank results, experimental exclusion, exact 110-item ownership, 150-minute timing, six scored-domain denominators, 100/100 with all ten experimental answers wrong, and review of all 440 option explanations. The new expiry test advances the test clock past 150 minutes, checks automatic submission with 100 scored blanks despite a correct experimental answer, and verifies a fresh retake has no answers, flags or revelations. Complete-but-held, incomplete and mis-scored forms fail closed.

The browser fixture now runs the entire 110-item form at **320, 390 and 1440 px, light and dark, Chromium and WebKit** instead of only desktop/light. Each case checks all answer controls, 100/100 scoring, 110 review cards, 440 explanations, keyboard answer/flag persistence, reveal denial, domain scores, overflow/header geometry and active/review axe scans. Theme assertions after reload prevent accidentally counting a light-mode run as dark-mode coverage. Existing Diagnostic, Learning and broader site browser assertions remain intact. The workflow budget increases from 30 to 45 minutes for the additional full-form cases; assertions are not removed or relaxed.

Exact-head GitHub Actions results and artifact evidence are recorded in PR #301 after these changes run. Local and CI success are implementation evidence, distinct from content approval and live-account evidence.
